Tsk - Не таск-менеджер

У меня дилемма - менеджер задач
необходим всегда. Задачи начинают
вмещать в себя весь контекст работы и
строчки задач распухают до карточек, а
потом и до документов.

Варианта, остаётся два - либо
придерживаться минимализма в каждой
сфере - задачи отдельно, документация
отдельно (`TODO.(md|txt)`, `CONTINUITY.md`, `/docs`), и всё
вместе тухнет. Либо прибегать к
огромным монстрам систем управления
проектами - а это целая индустрия.

Надо проще. В основе всего -
спецификация документа. Хорошо
оформленный документ - уже задача.

## Использование

```sh
node bin/tsk.ts list .     # все карточки: путь(статус), заголовок
node bin/tsk.ts next .     # что можно брать сейчас
node bin/tsk.ts check .    # гейт: ERROR = exit 1
node bin/tsk.ts serve test/fixtures --port 8931
```

CLI работает под node ≥ 23.6 (нативный type-stripping) и под bun одинаково;
bun — путь разработки (тесты, гейты `bun run check:full`).
